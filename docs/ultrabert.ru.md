# Смысловой поиск UltraBERT

UltraBERT-Embed-150M рекомендуется для английского текста, BERTA — для русского.
Смена языка интерфейса меняет только рекомендацию: выбранная модель и индексы
сохраняются.

Откройте **Настройки → Модели → Модель текста**, выберите **UltraBERT-Embed-150M**.
Если текстовый индекс уже существует, отдельно разрешите смену модели и его
перестройку. Перестраивается смысловой индекс сообщений и распознанного OCR;
исходные сообщения, изображения и кэш распознавания сохраняются. Векторы BERTA,
UltraBERT и прежних E5 имеют разные пространства, даже если размерности совпадают.
Существующие индексы E5 продолжают работать.

Проверяемый набор ONNX с токенизатором и метаданными занимает около 306 МБ.
Приложение выполняет инференс через ONNX Runtime без Torch и запуска Python-кода
из репозитория модели. Путь к модели показан в подробностях карточки. Локальные
наборы и автономная работа используют те же проверки контрольных сумм.

Матрицы хранятся в FP16 и перед вычислениями восстанавливаются в FP32. Вычисления,
CLS pooling и L2-нормализация остаются FP32. Это уменьшает загрузку и размер на
диске; ускорение или сокращение занятой RAM этим не гарантируются. Запрос получает
инструкцию исходной модели, документы — без префикса. BOS и padding имеют ID 0,
валидность определяет attention mask. Вместимость исходной модели — 32 768
токенов, но приложение сохраняет ограничения 512 для запроса и 480 для чанка.
Лимит восьми содержательных сообщений в чанке не меняется.

## Проверки

- [Сравнение с исходной моделью на CPU](benchmarks/ultrabert-cpu.json): токенизация
  совпала точно; максимальная ошибка нормализованного вектора — менее 0,000166.
- [Совместимость ORT 1.23.2 и 1.30.0](benchmarks/ultrabert-runtime-parity.json):
  максимальное расхождение векторов менее 0,0000005 на одном графе.
- [Поиск по английской синтетической выборке](benchmarks/ultrabert-retrieval-en.json):
  144 сообщения, три временных диалога, 54 запроса и две проверки пустых фильтров.
  Recall@10 и nDCG@10 смыслового и комбинированного поиска — 1,0. Небольшая вручную
  составленная выборка не доказывает качество на реальной переписке. Повторные
  запросы могут попадать в кэш; задержки не являются сравнением холодных запросов.

Все замеры выполнены на CPU. Производительность CUDA/CoreML не проверена;
перед активацией другого provider приложение проверяет его совместимость с CPU.

Воспроизведение на отдельном тестовом workspace:

```bash
uv run telegram-search --workspace ./workspace prepare-model --profile ultrabert
uv run python scripts/benchmark_semantic.py --workspace ./workspace \
  --profile ultrabert --language en --output ./workspace/ultrabert-retrieval-en.json
```

Первая команда активирует модель в указанном workspace. Benchmark создаёт и
удаляет отдельную временную базу только с
[публичными синтетическими сообщениями](../tests/fixtures/synthetic/relevance.en.json).
Конвертация и публикация файлов описаны в
[инструкции отдельного окружения](../tools/ultrabert-export/README.md).

[Закреплённая исходная модель](https://huggingface.co/dmis-lab/UltraBERT-Embed-150M/tree/b06b36724c5417a1ec1b7863dd4fa542b74e4899)
распространяется под Apache-2.0.
