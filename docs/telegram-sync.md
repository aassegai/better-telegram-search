# Подключение Telegram

[English](telegram-sync.en.md) · Русский

Это необязательный источник новых сообщений для уже импортированного архива.
Приложение получает сообщения, редакции, события удаления и новые изображения
выбранных облачных диалогов одного аккаунта. Оно не отправляет, не редактирует и
не удаляет сообщения в Telegram и не отмечает их прочитанными. Secret Chats и
автоматическое объединение мигрировавших групп не поддерживаются.

## Настройка приложения разработчиком

Для исходников установите `uv sync --locked --extra semantic --extra ocr --extra telegram`.
Разработчик получает собственные `api_id` и `api_hash` приложения через
[Telegram](https://core.telegram.org/api/obtaining_api_id). Не используйте sample ID.
Пользователю подготовленной сборки регистрировать developer app не нужно.

При запуске из исходников передайте `BTS_TELEGRAM_API_ID` и `BTS_TELEGRAM_API_HASH`
через окружение или поместите их в `workspace/private/telegram.toml`:

```toml
[telegram_sync]
api_id = 123456
api_hash = "replace_with_your_32_character_hex_hash"
```

Значения выше — заглушки. Файл приватный, его нельзя коммитить. Ограничения ресурсов
можно скопировать из [configs/telegram.example.toml](../configs/telegram.example.toml).
Перезапустите приложение после изменения файла.

Для нативных сборок задайте GitHub Actions secrets `TELEGRAM_API_ID` и
`TELEGRAM_API_HASH`. Сборщик помещает только эти реквизиты developer app в backend
пакета, не во frontend. Они извлекаемы из дистрибутива и не являются авторизацией
пользователя. При отсутствии реквизитов сборка сохраняет поиск/импорт, но подключение
Telegram недоступно. Все платформы включают дополнительный SDK Telethon; Torch не нужен.

## Подключение и управление

1. Откройте **«Источники · Telegram»**, введите телефон с кодом страны, код входа
   и пароль двухэтапной проверки, если его запросит Telegram. Код поступает способом,
   выбранным Telegram; доставка по SMS не гарантируется. Вход истекает через 5 минут.
2. Нажмите **«Показать диалоги Telegram»**. Фильтр действует на текущую страницу;
   используйте следующую страницу для остальных диалогов.
3. Выберите локальную выгрузку или новый диалог с начальной датой UTC. Проверка
   сравнит до 20 сообщений. Расхождение типа/ID или неподтверждённых данных блокирует
   привязку. Проверьте аккаунт и подтвердите её вручную.
4. Меню **⋯** диалога показывает курсор догрузки, состояние прохода, ошибки фото и
   готовность индексов. Здесь можно приостановить источник, обновить сейчас, повторить
   ошибки и отключить привязку. Готовые сообщения остаются при паузе и отключении.

Старая история до последнего ID выгрузки используется как исходная база; её полнота
не доказывается и пропуски старого экспорта автоматически не догружаются. Для нового
диалога загружается доступная история после выбранной даты. Обработка идёт страницами
по 100 сообщений, до 20 страниц за проход, затем продолжается с сохранённого курсора.
Периодическая проверка редакций: каждые 15 минут, последние 7 дней по умолчанию.
Отсутствие сообщения в странице не считается удалением. Старые редакции за пределами
окна могут остаться неизвестными. Приложение должно быть запущено для синхронизации.

Новые изображения загружаются в `workspace/data/media/telegram/`. По умолчанию:
до 40 МиБ на файл, не более двух загрузок, квота 20 ГиБ и минимум 512 МиБ свободного
места. Только проверенные изображения публикуются в поиске. Одинаковые файлы
переиспользуются; бесхозные файлы удаляются после 24 часов. Исходные файлы Desktop
не удаляются. Старые недоступные фотографии выгрузки автоматически не догружаются.

Политика **«Сохранять архивную копию»** помечает удалённое сообщение; поиск может
скрыть такие сообщения отдельным флажком. **«Удалять из локального поиска»** удаляет
копию и поисковые фрагменты после события Telegram. Политика действует на последующие
события. Старый JSON не восстанавливает удалённые записи и не затирает новые API-редакции.
При неоднозначной редакции сохраняется текущая версия и показывается число конфликтов.
При обновлении смыслового индекса архивные записи отделяются от живых сообщений,
чтобы скрытие удалённых не убирало из выдачи их соседей.

## Сессия и диагностика

Сессия даёт доступ к аккаунту и хранится **без шифрования** в
`workspace/private/telegram/<connection-id>.session`. На POSIX каталог имеет права
700, файл — 600; на Windows используется приватный каталог профиля пользователя.
Не передавайте эту папку другим людям. `tdata` и существующие сессии не импортируются.
OTP/пароль не сохраняются в базе, логах и browser storage. Статус API не возвращает
auth key, session string, `api_hash`, телефон или приватные сообщения.

**«Отключить Telegram»** закрывает соединение, сохраняя сессию и архив.
**«Выйти из Telegram»** отзывает текущую сессию и удаляет её локально. Если серверный
выход не подтверждён, завершите эту сессию в Telegram → Настройки → Устройства.
Архив сохраняется. После выхода привязки допускают только тот же аккаунт, пока они существуют.

Ошибки и время следующей попытки видны в источниках и карточке диалога. FloodWait
соблюдается; повтор не обходит задержку. `/api/telegram/connection`,
`/api/chats/{chat_id}/telegram` и `/api/sync/runs/{run_id}` возвращают безопасный статус.
Офлайн-тесты используют синтетический адаптер; реальная авторизация и файловые права
Windows/macOS требуют проверки на соответствующей системе.
