# Статистический анализ шума: состояние реализации

[English](noise-analysis.md)

[Воспроизводимый CPU-бенчмарк и локальная оценка](noise-evaluation.ru.md)

CPU-сервис собирает ограниченный приватный отчёт по выбранному диалогу.
Исходные сообщения и поиск по словам всегда сохраняются. Анализ не меняет
действующие правила и checkpoint; явное применение перестраивает только текст.
Локальный API поддерживает проект точных правил и переопределения. Панель диалога и CLI
используют те же сервисы. Dry-run по реальным токенам доступен в отдельном CLI и
как отменяемая фоновая задача в настройках диалога. Калибровка ещё не выполнена.
**Автоматическое исключение новых форм выключено.** Новые неоднозначные формы
сохраняются до явного исключения; ранее выбранные ручные правила остаются.

## Гипотезы и решения

Модули `search/chunking/noise/` разделяют нормализацию полного сообщения,
индексированный подбор кандидатов, статистику, лексикон и оценки. Поддерживаются
одна вставка, пропуск, замена, перестановка соседних символов, прямое растягивание
букв, повтор блока до четырёх символов и чередующийся русский смех. Повторы имеют
отдельные метки операций. Нет расстояния два, транслитерации, смены раскладки и
транзитивного расширения seeds. Сохраняется гипотеза исходной формы: синтетическое
«бял» может конкурировать и с «бля», и с «был».

Отдельно считаются полные сообщения, допустимые для фильтрации вхождения,
частоты внутри фраз, разные дни и авторы. Авторы представлены только счётчиками
и внутренними хешами с солью на один запуск; имён и ID в отчёте нет. Полные фразы
и соседние сообщения в отчёт не копируются. Подписи к вложениям, структурированные
ссылки/код/упоминания и ответы на вопросы защищены в каждом вхождении. Новые формы
также сохраняют признаки регистра, чисел, смешения письменностей и составных
терминов. Исключённые отправители не участвуют даже в поиске родительского вопроса.

Текущая оценка — `log1p(частота_полных_сообщений + частота_во_фразах)` с равными
весами ошибок. Она **не откалибрована и не является вероятностью**. Видны полезные
и исходная гипотезы, а также разница оценок. Известные формы и неизвестные формы
без шумовой гипотезы сохраняются; новые неоднозначные идут в review. Omit может
относиться только к уже подтверждённым точным seeds; защищённые вхождения остаются.
Сам анализ ничего не применяет. Сумма семейства не определяет судьбу его вариантов.

## Локальный API

Префикс: `/api/chats/{chat_id}/noise-analyses`. Сохраняются проверки локального
сеанса, Host и Origin. Изменяющие запросы требуют `X-Session-Token` из `/api/session`.

| Запрос | Результат |
| --- | --- |
| `POST` с необязательными лимитами | `202`, ID задания и прогресс |
| `GET` | До восьми сохранённых заданий |
| `GET /{id}` | Состояние, время, прогресс и сводка |
| `POST /{id}/cancel` | Отмена, доступная и при обслуживании векторной БД |
| `GET /{id}/forms?decision=review&offset=0&limit=50` | Страница форм, гипотез и защит |
| `GET /{id}/families?offset=0&limit=50` | Описательные агрегаты семейств |
| `DELETE /{id}` | Удаление остановленного задания и его локального отчёта |
| `GET /{id}/draft` | Лёгкие метаданные проекта, ревизии и применения |
| `PATCH /{id}/draft` | Замена overrides: `{ "revision": 0, "overrides": { "бял": "keep" } }` |
| `POST /{id}/preview` | Явный предпросмотр: `{ "revision": 1 }` |
| `POST /{id}/apply` | Явное перестроение текста: `{ "revision": 1 }` |
| `POST /{id}/dry-runs` | `202`, CPU-сравнение с ревизией проекта и лимитами сообщений/времени |
| `GET /{id}/dry-runs` | Последнее сравнение или `null`, без сканирования/подготовки моделей |
| `GET /{id}/dry-runs/{comparison_id}` | Статус, прогресс и измеренный результат в заданном scope |
| `POST /{id}/dry-runs/{comparison_id}/cancel` | Отмена, включая устаревшую задачу и очистку векторов |

По умолчанию: `max_messages=100000`, `max_forms=50000`, `time_limit_seconds=300`.
Максимумы: миллион сообщений, 50 000 форм отдельно для полных сообщений и фраз,
час работы, 100 записей на страницу. В workspace один CPU-поток анализа,
не больше одного задания на диалог и восьми сохранённых отчётов. Размер каждого
отчёта ограничен 128 МиБ. Перед девятым удалите ненужные. Ограничения источника,
времени, гипотез и подробностей видны явно. Неполный источник блокирует применение;
ограниченные гипотезы не разрешают автоматическое исключение новых форм.
Измерения CPU и выборочный RSS не выдаются за экономию GPU.

Основная БД читается короткими порциями по времени и ID сообщения. Обработка
текста выполняется без соединения с архивом и без write/lifecycle lock. Подробный
отчёт хранится в `workspace/data/noise-reports/`, в основной БД — небольшие записи
заданий. Занятый writer не убивает поток; готовность публикуется после сохранения
результата. При постоянной ошибке SQL выполняется одна защищённая попытка записать
ошибку. Если она тоже неудачна, задания показывают фиксированный сбой, приём новых
анализов закрывается до перезапуска; бесконечных повторов нет. После перезапуска
задания не продолжаются автоматически. Polling и
`/api/doctor` не запускают анализ и не скачивают модели.

Отчёт привязан к ревизии, исключениям, политике и эпохе архива. После изменения
области его чтение отклоняется. Проверка эпохи консервативна: изменение другого
диалога тоже может сделать отчёт устаревшим. Клиент не задаёт пути отчётов;
symlink/junction, неверные ID/версии, повреждение и превышение размера отклоняются.

## Закреплённый лексикон и лицензия

Встроены 39 532 нормализованные формы из первых 20 000 русских и 20 000 английских
записей [wordfreq 3.1.1](https://pypi.org/project/wordfreq/3.1.1/), автор Robyn Speer.
Это ограниченный частотный справочник, **не доказательство правильного написания**;
отсутствие в нём не означает шум. JSON размером 757 479 байт содержит исходные
credits, лицензии, хеши источников и описание преобразований. Производные данные
распространяются по [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/),
код wordfreq — Apache 2.0. Сохранены указания источников корпусов и свободно
доступных данных SUBTLEX, Marc Brysbaert et al. При распространении производного
лексикона сохраняйте attribution. JSON включается в нативные сборки.

Воспроизведение в отдельном закреплённом окружении сборщика:

```sh
uv run --locked --project tools/noise-lexicon python tools/noise-lexicon/prepare.py
```

SHA-256: `a296a46493fbfbb2475742f3abbb7bd05ca1743d059f293acf34b0761a3ed602`.
Приложение проверяет хеш; wordfreq в runtime не требуется и не импортируется.
Окружение сборщика исключено из git. Сетевых обращений при анализе нет.

## Проверки и дальнейшая работа

Синтетические тесты проверяют расстояние редактирования, защиты, конкуренцию
оценок, редкие формы, исключения и ревизии, pagination, отмену на CPU-этапах,
блокировки SQLite, валидацию отчётов и миграцию схемы 17. Зафиксированы старые
JSON/hash v2. Реальные архивы тестами не читаются; синтетика не валидирует отсев
на реальной переписке.

Остаются: разметка development/test, CPU-бенчмарки корпуса и валидированный
консервативный автоматический гейт.
OCR и визуальные индексы этим фильтром не обрабатываются. До измерений нет
утверждений об ускорении или улучшении качества выдачи.

## Замороженная точная политика и явное применение

Отдельный формат `NoisePolicy` объединяет неизменённую политику эпизодов v2,
канонические точные omit/keep и версию защит. Закешированные JSON/hash содержат
только действующие правила. Ручной keep побеждает, в том числе для старого seed.
Частоты, время анализа и ID отчёта не меняют идентичность. У legacy/v2 сохраняются
прежние JSON/hash, checkpoint и путь заимствования контекста.

Только в новом формате заимствованные родители проходят те же защиты, что свои
сообщения. Пропущенный родитель остаётся зависимостью: изменение инвалидирует
дневной сегмент и может вернуть полезный текст. Один дополнительный ограниченный
lookup сохраняет ответ на вопрос без рекурсивной классификации. Импорт и смена
модели сохраняют явно выбранную новую политику, паузы и остальные индексы.

Для preview, overrides и применения нужен актуальный отчёт с полным покрытием
источника и сохранённым SHA-256. Старые отчёты можно просматривать; при отсутствии
нужных метаданных запустите новый анализ. Неполный источник блокирует применение.
При запуске приложения политики не переключаются.

Версия сводки `source-and-evidence-v1` разделяет `source_complete` и
`evidence_complete`. `complete` сохраняет строгое значение: при любом ограничении
он false. Если все сообщения/формы обработаны, но ограничен список гипотез или
его подробности (`candidate_limit`/`payload_limit`), задача может быть `ready` с
`policy_applicable=true`. `limited_evidence_forms` считает такие формы. Можно
применить только подтверждённые точные seeds и явные overrides, с выключенным
новым автоотсевом. У обычного «да» бывает больше 16 полезных гипотез; ограничение
их вывода не должно блокировать точные правила для полностью просмотренного чата.
Оценки по-прежнему не откалиброваны. Незавершённый поиск кандидатов, не нашедший
совпадения, даёт review, а не доказательство отсутствия шумовой гипотезы.

Лимиты сообщений, форм, слов фраз, текста и времени продолжают запрещать применение.
Неизвестные лимиты/версии, противоречивые флаги и смешанные форматы без версии
отклоняются. Старые полные отчёты с SHA совместимы; старые неполные отчёты не
становятся применимыми автоматически. Интерфейс объясняет полноту источника при
ограниченных гипотезах и необходимость повторить несовместимый анализ.

Допустимы overrides `keep`/`omit` для 1 000 нормализованных форм из отчёта. Сохранение
проверяет ревизию проекта; устаревшие правки возвращают `409`. Preview компилирует
правила без применения. Хеширование и компиляция не держат основной write или
lifecycle lock. Применение повторно проверяет ревизии внутри транзакции, сохраняет
неизменяемую политику и планирует все дни через SQL без перебора сообщений.
Паузы, батчи, устройства, OCR и визуальные индексы сохраняются.

Ручные правила выбранной политики переживают повторный анализ до явного изменения.
Если действующие правила не изменились, новые частоты не перестраивают чанки и не
инвалидируют поисковые snapshots. Повтор того же применённого проекта — no-op,
в том числе после последующего импорта. Обязательной ручной проверки каждой формы
нет: спорные сохраняются, overrides доступны по желанию. Этот API-сценарий не
валидирует новый автоматический отсев и не означает измеренную экономию GPU.

## Отдельный CLI

Перед командами остановите приложение. CLI получает общую writer lease workspace,
чтобы второй процесс не восстанавливал задания работающего приложения. Он
использует те же сервисы, что API, без загрузки моделей инференса и запуска web server.
Явный dry-run загружает только уже скачанный токенизатор.

```sh
uv run telegram-search --workspace ./workspace noise analyze --chat-id CHAT_ID
uv run telegram-search --workspace ./workspace noise list --chat-id CHAT_ID
uv run telegram-search --workspace ./workspace noise status --chat-id CHAT_ID --job-id JOB_ID
uv run telegram-search --workspace ./workspace noise override --chat-id CHAT_ID --job-id JOB_ID --revision 0 --keep FORM
uv run telegram-search --workspace ./workspace noise preview --chat-id CHAT_ID --job-id JOB_ID --revision 1
uv run telegram-search --workspace ./workspace noise apply --chat-id CHAT_ID --job-id JOB_ID --revision 1
```

`analyze` ждёт завершения; Ctrl+C отменяет работу и дожидается потока до освобождения
lease. Лимиты совпадают с API. При неполном источнике отчёт доступен для просмотра, но не применения.
При failed/stale код выхода — 1. `override` принимает несколько `--keep`, `--omit`
и `--clear`; если форма передана и в keep, и в omit, побеждает keep.

Обычный JSON содержит агрегаты, ревизии и непрозрачные ID заданий, без имён/ID
диалогов, авторов, путей и форм. Для намеренного просмотра форм:
`noise report --chat-id CHAT_ID --job-id JOB_ID --show-private`; доступны
`--kind forms|families`, `--decision keep|review|omit`, `--offset`, `--limit`.
`noise delete --chat-id CHAT_ID --job-id JOB_ID` удаляет остановленный отчёт.

## Сравнение по реальным токенам (отдельный CLI)

После сохранения переопределений сравните замороженный проект без применения:

```sh
uv run telegram-search --workspace ./workspace noise dry-run --chat-id CHAT_ID --job-id JOB_ID --revision 1 --max-messages 100000 --time-limit-seconds 300
```

Нужны актуальный анализ с полным покрытием источника и локальный токенизатор активной текстовой модели.
Проверяются оба файла токенизатора по закреплённому manifest, идентичность embedding
space и версия установленного tokenizers. При отсутствии или несовместимости —
понятная ошибка. Модели не скачиваются; ONNX-веса, сессии инференса и GPU не
загружаются. Как и перед остальными отдельными командами, остановите приложение.
Ctrl+C освобождает writer lease.

Два потоковых CPU-прохода используют настоящие прежний/текущий и предложенный
чанкеры. Учитываются prefix, специальные токены, авторы, заимствованный контекст,
overlap и разрезание длинных сообщений. Батчи по порядку чанков завершаются на
границе UTC-дня. `batch_basis` явно фиксирует настроенный размер батча: будущий
OOM backoff и изменения настроек предсказать нельзя. Экономия токенов и паддинга
**не является оценкой времени или ускорения GPU**.

В `before`/`after`: чанки, токены, батчи, padded slots, padding, уникальные собственные
сообщения и старый skipped count как source-minus-own. Overlap и части одного
длинного сообщения считаются один раз; borrowed context не становится собственным
сообщением. `noise_only_chunks` — все модельные части являются точными шумовыми
формами без borrowed context; это не разрешение удалить эти векторы. Счётчики
классификации для legacy-окон недоступны (`classification_available=false`).
Сохранённые защиты и review — отдельные наблюдения, их нельзя складывать в skipped.

`delta` — **после минус до**, плюс числа исчезнувших/восстановленных собственных
сообщений. Лимит сообщений сравнивает один и тот же хронологический префикс:
`comparison_complete=true`, `complete=false`, `limits=["message_limit"]`.
При обрыве прохода по времени или размеру входа delta отсутствует. Слишком длинные
тексты, авторы, ID и метаданные останавливают сравнение, а не молча обрезаются.
Контекст может находиться вне измеряемого префикса, как и при обычной индексации;
исключения отправителей действуют и для него.

Изменение источника, исключений, проекта, модели или размера батча отвергает
завершённое сравнение. Основная БД читается короткими keyset-порциями; CPU-подсчёт
не удерживает соединение архива, lifecycle lock или write transaction. Уникальные
ID считаются в отдельной безымянной временной SQLite с лимитом 128 МиБ; кэш
контекста ограничен. Результат содержит только агрегаты/хеши, wall/thread CPU
seconds, sampled peak RSS **всего процесса** и baseline. Исходные сообщения,
авторы, ID чата и пути не выводятся. Индекс, checkpoint и неизменяемый отчёт
анализа сохраняются. Команда CLI не сохраняет сравнение; фоновый API/интерфейс
приложения хранит один последний результат отдельно от неизменяемого отчёта.

## Фоновое сравнение в настройках диалога

После сохранения переопределений нажмите **Сравнить фрагменты и токены**.
Лимиты по умолчанию — 100 000 исходных сообщений и 300 секунд; они не связаны с
лимитами анализа. В первом проходе прогресс неопределённый, но счётчик сообщений
измеряется. Второй проход может использовать объём первого. Выдуманной оценки
завершения нет. Отмена сохраняет индекс и действующие правила.

В результате видны фрагменты, токены и уникальные собственные сообщения;
подробности содержат паддинг, пропуски/защиты, время CPU и RSS процесса.
Ограниченные префиксы и незавершённые проходы помечены явно. Разница показывается
только после завершения и проверки источника, включая явно отмеченный частичный
префикс. Новые правки сначала сохраните; сравнение не применяет правила.

Схема 20 добавляет отдельную таблицу `noise_dry_runs`. Для каждого анализа хранится
одно последнее сравнение, всего не больше восьми. Новый запуск заменяет только
предыдущее остановленное сравнение. Один CPU-поток сравнения владеет максимум
восемью задачами; у анализа такой же отдельный предел владельцев. Лимит действует
и после каскадного удаления метаданных чата. Активное сравнение защищает удаление
и GC своего отчёта до освобождения. Чтение статуса не держит lifecycle lock и
не открывает приватный отчёт или токенизатор. При временной ошибке чтения известная
задача сохраняет кнопку отмены, а удаление родительского отчёта остаётся закрытым.

При запуске фиксируются анализ, ревизия проекта, source fence, активное embedding
space и размер батча. Worker проверяет их до и после загрузки локального
токенизатора, а затем перед публикацией в короткой транзакции. При изменении scope
старый результат скрывается; устаревшую активную задачу можно отменить. После
перезапуска незавершённые задачи становятся interrupted и сами не запускаются.
Общая публикация переживает SQLite BUSY и выполняет только одну защищённую попытку
записать permanent failure. При повторной ошибке новые задачи блокируются до
перезапуска; результат не выдаётся как сохранённый. ONNX-веса, GPU-сессии и загрузки
моделей этим сравнением не запускаются.

## Настройки диалога

Откройте настройки индексации диалога и разверните **Фильтр смыслового шума**.
Запустите анализ с текущими исключениями отправителей. Лимиты доступны для
изменения; UI по умолчанию выбирает миллион сообщений и 300 секунд. Видны этап,
счётчики и прошедшее время; есть отмена, без выдуманного срока завершения.

Просматривайте страницы форм или семейств. У формы раздельно показаны решение
анализа, правило проекта и ранее выбранное правило. Поэтому новая неоднозначная
гипотеза может сохранять прежнее явное исключение. Новое переопределение побеждает;
**Без нового переопределения** возвращает наследованное/базовое правило. Подписи,
entities и значимые ответы сохраняют защиты каждого употребления.

Правки не теряются при polling и смене страниц. Сохраните overrides, просмотрите
правила и явно примените их с перестроением текста. Предпросмотр принадлежит одной
ревизии: обновление изменённого проекта его сбрасывает, Apply не отправляет более
новую непросмотренную ревизию. Итог включает унаследованные правила. Неизменившиеся
правила не запускают повторное перестроение.

При неполном источнике и в старых отчётах без SHA доступно только чтение. Смена источника
или исключений скрывает старые данные и требует нового анализа. Закрытие настроек
и смена диалога, политики или авторов не дают позднему ответу попасть в новое окно.
Панель работает на ru/en и в обеих темах. Формы показываются буквально и не
передаются в переводчик интерфейсных строк.
