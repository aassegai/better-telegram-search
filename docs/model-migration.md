# Текстовые и визуальные модели

Новые подготовки рекомендуют BERTA FP16 для текста и смыслового OCR и
SigLIP 2 base/patch16/224 для изображений. Старые E5 small/base и CLIP остаются
доступны. Обновление приложения само не переключает модели и не перестраивает индексы.

| Модель | Назначение | Размерность | Подготовка |
| --- | --- | --- | --- |
| BERTA | Сообщения и смысловой поиск распознанного OCR | 768 | Настройки → Модель текста |
| SigLIP 2 | Изображения по описанию, включая русские запросы | 768 | Настройки → Модель изображений |
| Giga | Необязательное уточнение порядка текстовых/OCR результатов | 1024 | Настройки → Уточнение результатов |

Для смены текстовой модели разрешите переиндексацию всех диалогов. BERTA получает
собственное пространство: E5-векторы не переименовываются и не смешиваются с новыми.
Пересчитываются сообщения и смысловые OCR-векторы; результаты распознавания, исходные
изображения, исключения авторов, правила чанкинга, батчи, устройства и паузы сохраняются.
Лимит чанка — 8 содержательных сообщений и 480 токенов выбранного токенизатора,
включая prefix и специальные токены. Сохраняемый короткий контекст расходует токены.

Для перехода CLIP → SigLIP 2 выберите модель и разрешите перестроение индекса
изображений. Меняются только визуальные векторы; распознавание OCR не повторяется.
Подготовка проверяет файлы, ONNX-контракт и пробные вычисления до активации. Ошибка
подготовки сохраняет действующие модели. Повторная подготовка без выбора профиля
использует активную модель, в том числе при восстановлении повреждённого набора.

## Giga

Сначала подготовьте модель, затем включите «Переранжирование Giga». Опция выключена
по умолчанию. Она кодирует запрос и до 50 разрешённых кандидатов каждой текстовой/OCR
ветки, сортирует по cosine и передаёт порядок обычному объединению RRF. Визуальная
ветка сохраняет свой порядок. Точные фразы и поиск только изображений пропускают Giga.
Основной индекс и поколения не меняются. Непереранжированный хвост сохраняет порядок.

Модель наследует устройство текстовых запросов, CPU-потоки и лимиты RAM/VRAM.
Подготовка и запросы проверяют доступную память; недостаток ресурсов, неподготовленная
модель или ошибка возвращают базовый порядок с объяснением. Вход ограничен 512 токенами
вместе с инструкцией; усечение явно сообщается. Кэш векторов ограничен 2048 записями
и 16 МиБ (или меньшей долей бюджета RAM), живёт в памяти и учитывает модель, содержимое
и ревизию workspace. Фильтры проверяются до и после обработки. «Показать ещё» читает
готовый SearchCache и не запускает Giga повторно.

В ответе поиска: `rerank_applied`, `rerank_reason`, `rerank_branches`; для веток —
число кандидатов, длительность, количество усечённых фрагментов и усечение запроса.
Для уточнённых результатов интерфейс показывает отметку Giga.

## Runtime и проверенные устройства

В пользовательском окружении нужны ONNX Runtime и tokenizers; Torch/Transformers
не устанавливаются. Загружаются только закреплённые ONNX, tokenizer/processor и
метаданные модели. Пути показаны в настройках. BERTA/Giga получаются из отдельно
проверяемых ONNX bundles; SigLIP 2 — из закреплённой согласованной публичной пары.
Каждый файл проверяется по размеру и SHA-256. Локальный кэш поддерживает offline.

Это mixed precision: веса FP16, явно сохранённые устойчивые участки FP32, pooling/L2
и сохранённые embeddings FP32. На CPU ORT может вставлять precision casts и выполнять
операции FP32; размер весов не означает аппаратное FP16-исполнение на CPU.

Проверены Linux x86_64 CPU, ORT 1.23.2 и 1.30.0: переменные батчи, входы до 512 токенов,
SigLIP 2 fixed64, формы/конечность/нормы, tokenizer/reference и processor/reference parity.
Максимальное расхождение нормализованных векторов между ORT — 0,000372;
минимальный cosine — выше 0,999999. Экспорты BERTA/Giga воспроизводят закреплённый SHA
и проходят сравнение с исходными FP32 моделями. Синтетический архив прошёл индексацию,
RU/EN поиск BERTA, визуальный поиск SigLIP 2 и запрос с Giga через адаптеры приложения.
Это проверка корректности, не оценка качества на пользовательском архиве.

Отдельный публичный синтетический набор: 144 сообщения, 54 запроса с разметкой и
2 пустых фильтра. Для BERTA смысловой и комбинированный поиск дали Recall@10 = 1,0
и nDCG@10 = 0,992. На этой машине p95 составил 50,25 мс и 27,88 мс соответственно;
повторные запросы могут использовать кэш. Запуск: `scripts/benchmark_semantic.py
--profile berta --workspace <workspace с моделью> --output <локальный отчёт>`.
Эти числа не предсказывают скорость или релевантность большой переписки.

На том же текстовом наборе с Giga nDCG@10 вырос до 1,0 при Recall@10 = 1,0.
Для смыслового/комбинированного поиска p95 составил 318,53/92,16 мс; первый
холодный rerank занял 13,81 с, пик RSS процесса — 3,42 ГиБ. Повторные запросы
использовали кэш запросов и кандидатов; уточнялись до 50 текстовых фрагментов.
Это небольшой синтетический эксперимент, а не гарантия выигрыша на реальных чатах.

На ORT 1.23.2 только для SigLIP 2 отключены `LayerNormFusion` и
`SimplifiedLayerNormFusion`: иначе этот граф попадает в ошибку CPU-оптимизатора.
CUDA/CoreML в этой работе не запускались. На выбранном устройстве приложение сравнивает
пробные векторы с CPU перед активацией; явный GPU при ошибке не превращается молча в CPU,
а Auto допускает CPU fallback. Допуски новых профилей не ослабляют проверки старых E5.

## CLI и подготовка разработчиком

```bash
uv run telegram-search --workspace ./workspace prepare-model --profile berta --reindex
uv run telegram-search --workspace ./workspace prepare-media --kind images --profile siglip2 --reindex
```

Экспорт и его отдельное CPU-окружение uv описаны в
[tools/model-export](../tools/model-export/README.md). Приложение не выполняет этот экспорт.
ONNX model bundles публикуются отдельным prerelease `model-bundles-v1`, который не
считается обновлением приложения. Новая версия приложения для этих изменений пока не объявлена.
