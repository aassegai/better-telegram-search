# Устройства и обновления

Рекомендуемый режим: GPU для фоновой индексации E5/CLIP, CPU для запросов. Оба
используют закреплённые ONNX-веса FP32, одинаковые tokenizer, pooling и L2;
TF32 на CUDA отключён. Устройство не создаёт отдельное пространство векторов.
Перестроение нужно при смене модели или обработки, а не CPU/GPU.

Для существующей базы 0.2.0 приостановите текст и медиа, полностью закройте приложение,
запустите актуальную версию с тем же workspace и выберите устройства. Сохраняются прежний space ID,
ID чанков, поколения сегментов и checkpoint. Продолжение кодирует только оставшиеся
чанки; новые поисковые запросы могут выполняться на CPU поверх смешанного индекса.

GPU загружается при обработке, а не при запуске с поиском на CPU. Сессии индексации
выгружаются при паузе/окончании: E5 не позднее пяти секунд простоя, CLIP после
исчерпания очереди изображений. Это освобождает память моделей; отключение питания
дискретной видеокарты зависит также от драйвера и других приложений и не измерялось.
Когда устройства одинаковые, E5 переиспользует одну сессию. Лимит CUDA относится к
арене одной сессии, не к общей VRAM; CoreML этот лимит не использует.

С 0.3.3 устройства E5 и CLIP выбираются независимо в карточках моделей в настройках.
В карточке OCR можно оставить прежний Tesseract на CPU или выбрать PaddleOCR RU/EN
на CPU, GPU либо Авто. Для NVIDIA нужен GPU-архив. PaddleOCR загружает около 10 МиБ
закреплённых ONNX-весов и словаря, без Torch или Paddle-фреймворка. Детекция текста
и распознавание строк используют выбранный ONNX provider; строки обрабатываются
микробатчами до восьми, с уменьшением при нехватке памяти. В строгом режиме GPU
ошибка загрузки останавливает обработку; Авто допускает CPU. CoreML может выполнять
часть графа на CPU. Скорость зависит от размера фотографий и загрузки видеокарты.

Кэш PaddleOCR общий для CPU/GPU и отличается от кэша Tesseract, поскольку модели
распознают текст по-разному. Смена устройства PaddleOCR сохраняет прогресс; смена
OCR-модели начинает её отдельную очередь, сохраняя прежние результаты. В меню диалога
OCR имеет отдельную паузу от изображений CLIP. Перед сменой устройства приостановите
индексацию и дождитесь завершения текущей порции.

NVIDIA поддерживается отдельными Windows/Linux x64 сборками. CPU и GPU extras uv
взаимоисключающие; GPU-окружение содержит ONNX Runtime GPU 1.23.2, CUDA 12 и cuDNN 9,
без Torch. Основной CPU-runtime закреплён lock на 1.30.0, macOS Intel — 1.23.2.
Совместимость этих версий проверяется на публичных E5 query/passages и CLIP text/images;
остальные версии не принимаются автоматически как эквивалентные старому индексу.
При первой загрузке каждого GPU-графа приложение сравнивает синтетические векторы
с CPU (max absolute error ≤1e-4, cosine ≥0.99999). Ошибка останавливает строгий GPU;
Авто использует CPU. CoreML может выполнять часть графа на CPU; скорость macOS не измерялась.

Обновления берутся из публичного GitHub Releases этого репозитория, без токена.
Приложение проверяет платформу, вариант CPU/GPU, SHA-256, отчёт нативной сборки и
запускает распакованную сборку с `--self-test`. Установка начинается только после
явной кнопки: старый процесс закрывается, отдельный помощник заменяет папку приложения,
сохраняя предыдущую сборку, SQLite и настройки. Workspace и модели остаются снаружи.
Новая версия разрешает фоновые записи после проверки здоровья и долговременного
подтверждения; потеря HTTP-ответа не отменяет подтверждённое обновление.

Если новая версия не запускается, помощник возвращает старое приложение и базу.
Если сам помощник был прерван между заменами папок, закройте процессы приложения
и запустите `Recover-BetterTelegramSearch-….cmd` (Windows) или `.sh` (Linux/macOS),
созданный рядом с папкой приложения. Он проверяет план, восстанавливает старую папку
и запускает её; подтверждённую новую версию не откатывает. После успешного обновления
при следующей проверке удаляются временные файлы и старые резервные копии; остаётся
одна предыдущая сборка и её снимок базы. Для обновления нужны права записи в папку
приложения и место для архива, распаковки, помощника и копий.
