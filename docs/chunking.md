# Текстовые фрагменты

В меню диалога откройте **Формирование текстовых фрагментов**. Политика
**Диалог с фильтрацией однословного шума** включается кнопкой
**Применить и переиндексировать текст**. Она перестраивает текстовые фрагменты
только выбранного диалога. Паузы, настройки устройств, картинки и распознанный OCR
сохраняются. Смысловой поиск по новым фрагментам становится доступен по мере
готовности дневных сегментов; поиск по словам остаётся доступен по всему архиву.

Лимит — **8 содержательных сообщений и 480 токенов** вместе с модельным префиксом,
именами и специальными токенами. Короткие ответы, отдельные термины, числа,
ссылки и эмодзи сохраняются и расходуют токены, но не лимит сообщений.
Содержательная подпись к вложению считается обычным сообщением. Дополнительный
предел — 32 исходных сообщения в одном окне; короткие реплики не создают
неограниченный буфер.

Одобренный однословный шум пропускается только в тексте смыслового индекса.
Эти слова внутри обычных фраз сохраняются. Подписи и структурированные сущности
защищены; ответ на вопрос также сохраняется. Исходная переписка, поиск по словам,
точная фраза и лексическая ветка комбинированного поиска доступны независимо
от фильтрации. Фото без подписи не создаёт текстовый вектор из одного `[фото]`.
Правила сообщений не применяются к распознанному OCR.

Короткий ответ может использовать до двух родителей из того же диалога, не
старше 30 дней, с общим бюджетом контекста 128 токенов. При отсутствии reply-связи
допускается предыдущая реплика в пределах двух минут с пометкой «Соседний контекст».
Контекст может пересекать UTC-полночь. Его изменения, удаление, поздний импорт
родителя или смена исключений авторов инвалидируют зависимые дневные сегменты.
Заимствованный контекст не подтверждает фильтр автора или даты основного сообщения.

Длинные сообщения делятся по абзацам, предложениям и словам; исходные Unicode-
диапазоны сохраняются, а соседние части имеют небольшой токенный overlap.
Исходные и модельные диапазоны хранятся раздельно. Соседние сообщения в карточке
не подавляют независимое совпадение.

**Исходные окна** сохраняют прежнее поведение: каждое сообщение расходует слот,
однословный шум не фильтруется. Обновление приложения оставляет существующие
индексы и checkpoint на этой политике, пока вы явно не выберете новую.
Смена правил создаёт новую генерацию; размер батча и устройство правил не меняют.
Фильтрация команд ботам без `/` и `@` пока отложена.

Для локального анализа явно выбранной выгрузки:

```sh
uv run --no-sync python scripts/analyze_chunking.py /path/to/result.json
```

Потоковый анализ не открывает рабочую базу приложения. Агрегаты и таблица кандидатов
записываются только в ignored `workspace/analysis/chunking/` (или явно выбранный
каталог внутри `workspace/`/`plans/`). Частотность сама по себе не добавляет слова
в политику. Отчёты содержат формы слов и предназначены для локального использования.
