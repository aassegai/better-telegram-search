# Оценка времени индексации

[English](indexing-estimates.en.md) · Русский

Оценка использует до 24 недавних успешно завершённых батчей для соответствующей
модели, устройства и настроек. Она появляется после трёх замеров. Размер батча,
лимит после нехватки памяти, CPU-потоки, лимиты GPU и настройки OCR разделяют
статистику. Общая очередь группируется по **текущим** настройкам оставшейся работы;
скорость прежнего большого батча не подставляется для нового маленького.

Время батча включает ожидание вычислительного ресурса, подготовку, чтение данных
и публикацию результатов. CPU-подготовка следующего батча может перекрываться с
инференсом: учитывается время, которое действительно задержало текущий батч.
Разовый прогрев модели и батчи с ошибками не задают скорость всей очереди.
Большие батчи имеют больший вес, недавние — больший вес, чем старые. Один выброс
ограничивается; повторяющееся замедление меняет прогноз.

- **Текст:** считаются оставшиеся токены с padding до самого длинного чанка
  каждого фактического батча. Уже записанный префикс и устаревшие поколения исключены.
  Для ещё не сформированных дней объём предварительно оценивается по переписке;
  отдельно прибавляется измеренное время формирования фрагментов.
- **Изображения:** считаются уникальные доступные фотографии. Вход визуального
  энкодера приводится к фиксированному размеру.
- **OCR:** считаются уникальные ещё не обработанные изображения. Сложность текста
  внутри них заранее неизвестна. CPU/GPU в совместном режиме измеряются отдельно,
  затем их производительность объединяется.
- **Смысловой OCR:** учитывается длина уже распознанного текста. Ещё не обнаруженный
  текст оценивается предварительно; при несовместимых неизвестных конфигурациях
  общий прогноз ждёт дополнительных данных.

Интерфейс показывает округлённый диапазон, а не обещанное время окончания.
Это практический диапазон по наблюдаемой скорости, не статистический доверительный
интервал. Для всей подготовки нижняя граница допускает перекрытие этапов, верхняя
учитывает их последовательное выполнение и зависимость OCR → текстовая модель.

Ошибки не входят в автоматически выполняемую очередь, пока не нажата кнопка
повтора. Пауза, блокирующая завершение очереди, скрывает срок, включая будущий
смысловой OCR. Давно не обновлявшиеся замеры перестают давать числовой прогноз:
порог — десять типичных длительностей батча, от минуты до часа.

Промежуточные объёмы кэшируются не более пяти секунд; прогресс обновляется отдельно.
Кэш общих медийных групп учитывает изменения архива, модели, пауз и настроек.
Хранятся только ограниченные числовые замеры и идентификаторы конфигураций,
без сообщений, распознанного текста, путей и файлов изображений.
Прежние усреднённые скорости не используются. Обновление не перестраивает индексы
и не сбрасывает сохранённые позиции индексации.
