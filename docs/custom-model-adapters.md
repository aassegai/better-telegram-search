# Пользовательские адаптеры моделей

[English](custom-model-adapters.en.md) · Русский

Локальный Python-адаптер подключает модель по опубликованному контракту роли без
изменения приложения. Он работает в **отдельном выбранном интерпретаторе**; его
зависимости не добавляются в готовую сборку. Встроенные модели используют ONNX
Runtime. Worker не является песочницей прав или сети: запускайте только доверенный
код в доверенном Python-окружении.

## Что подключено

Для пяти ролей — текст, изображения, reranker, OCR и ASR — работают проверка
manifest, отдельный процесс, проверка выходов, smoke test и сохранение регистрации.
**Текстовые адаптеры подключены к индексации и поиску, reranker — к оценке
кандидатов.** Остальные три пользовательские роли пока доступны только для
проверки контракта: их
регистрация не заменяет встроенную модель и не запускает индекс. Подключение этих
ролей и распознавание речи ещё реализуются. Smoke test не оценивает качество модели.

В **«Настройки → Модели → Добавить свою модель»**:

1. Выберите роль и локальный manifest. **«Проверить manifest и файлы»** проверяет
   данные и SHA-256 без импорта кода.
2. Укажите Python отдельного окружения и устройство. **«Запустить проверку и
   добавить»** явно запускает код на небольших публичных входах.
3. После успешной проверки сохраняется снимок пакета. Проверка не активирует модель.
4. Для текста выберите добавленную модель в карточке и подготовьте её. Замена
   существующего пространства требует явной переиндексации. Сообщения, исключения
   отправителей, распознанный OCR и визуальные векторы сохраняются.
5. Для reranker выберите модель в карточке переранжирования, сохраните, подготовьте
   и включите. Одна регистрация не переключает модель; переиндексация не нужна.

Изменение manifest после проверки требует новой проверки. Долгий job можно
отменить; финальное атомарное сохранение регистрации должно завершиться. Закрытие
настроек не останавливает job.

## Примеры и отдельное uv-окружение

[Шаблоны](../examples/custom-adapters/adapter.py) демонстрируют контракт: хешированный
словарный вектор, RGB/цветовые векторы, лексический reranker, OCR маленьких bitmap
цифр и обработка тишины для ASR. Это **не готовые нейросетевые модели**. ASR-пример
отклоняет нетихий звук вместо выдумывания транскрипта; для речи подключите настоящий
локальный runtime.

Используйте тестовый workspace:

```sh
uv sync --project examples/custom-adapters --locked --python 3.12
uv run --no-sync telegram-search --workspace ./workspace/adapter-demo adapters inspect \
  examples/custom-adapters/text_embedding.manifest.json
uv run --no-sync telegram-search --workspace ./workspace/adapter-demo adapters validate \
  examples/custom-adapters/text_embedding.manifest.json \
  --python examples/custom-adapters/.venv/bin/python --register
uv run --no-sync telegram-search --workspace ./workspace/adapter-demo adapters list
```

На Windows путь к Python — `examples/custom-adapters/.venv/Scripts/python.exe`.
`inspect` и `list` не запускают код и не открывают базу переписки. `validate`
запускает код; `--register` сохраняет пакет только после успеха. Полная identity
возвращается в отчёте. Подготовка зарегистрированной текстовой модели:

```sh
uv run --no-sync telegram-search --workspace ./workspace/adapter-demo prepare-model \
  --profile custom:<identity-из-отчёта>
```

`--reindex` добавляйте только для намеренного перестроения существующего индекса.
Текстовый адаптер также кодирует смысловой OCR. Сохраняются текущие фильтры,
публикация поколений и очистка векторов.

После правки примера создайте свежие manifest в **новой** папке:

```sh
uv run --project examples/custom-adapters --locked python \
  examples/custom-adapters/make_manifests.py --output ./workspace/new-adapter-packages
```

## Manifest и identity

Полный [пример текстового manifest](../examples/custom-adapters/text_embedding.manifest.json)
и файлы остальных ролей лежат рядом. Обязательны:

| Поле | Контракт |
| --- | --- |
| `schema_version`, `adapter_api_version` | Целое `1` |
| `id`, `revision`, `role` | Стабильное имя, версия обработки, одна из пяти ролей |
| `entrypoint` | Относительный `.py` и класс, например `adapter.py:TextEmbedding` |
| `supported_languages`, `devices` | Языки и доступные `cpu`/`gpu` |
| `runtime`, `dependencies` | Runtime и точные версии установленных distributions |
| `files` | Пути, размеры и SHA-256 необходимых файлов кода, модели и данных |
| `preprocessing` | Версия и параметры обработки, query/document prefixes текста |
| `input_contract`, `output_contract` | Лимиты и параметры роли |
| `network` | `false`: локальный инференс |

Для stdlib-примеров используется `runtime: {"name":"python","version":"3"}`.
Другой runtime, например `onnxruntime`, должен иметь точную запись в dependencies.
Устанавливайте зависимости через uv в выбранное окружение. Приложение не ставит
пакеты и не скачивает случайные удалённые ID моделей.

Identity manifest включает код/данные, обработку, префиксы, размерность и объявленные
зависимости. Регистрация также фиксирует версию Python и версии **объявленных**
distributions; worker проверяет их при запуске. Это не криптографическая проверка
всего окружения: перечисляйте все влияющие зависимости. Для изменения уже
зарегистрированного окружения измените revision и пройдите проверку снова.

Снимок хранится в `workspace/models/custom-adapters/<identity>`. Копируются только
закреплённые файлы. Ссылки, junction, выход за папку, лишние незакреплённые файлы и
ошибки SHA отклоняются. Не записывайте кэш или bytecode в неизменяемый пакет.
Меняйте исходный пакет и manifest, а не сохранённый снимок. Workspace внутри Git
обязательно должен быть исключён через `.gitignore`.

## Python API

Класс создаётся без аргументов и реализует:

- `info()` → `{adapter_api_version: 1, role, devices, operations}`.
- `validate(context)` — локальные проверки без скачивания.
- `load(context)` — загрузка; `unload(context)` — освобождение модели.
- `close(context)` — освобождение оставшихся ресурсов и фоновой работы.

В context доступны `package_root`, `device`, `gpu_device_id`,
`gpu_memory_limit_mib`, `cpu_threads`, `batch_size`, `offline=True`. Сам адаптер
применяет настройки потоков/устройства/памяти своего runtime; это не квоты ОС.
В циклах вызывайте `context.checkpoint()`; для реального прогресса —
`context.progress(completed, total, unit="items", phase="inference")`. Единицы:
`items`, `tokens`, `seconds`, `bytes`. Phase — короткий lowercase identifier, не
входной текст. Также доступен `context.is_cancelled()`.

| Роль | Метод | Выход |
| --- | --- | --- |
| Текст | `count_tokens(texts, context)` | По целому счётчику на текст; работает до `load` |
| Текст | `encode_text(items, operation, context)` | `{ids, dtype: "float32", vectors: [[...]]}` |
| Изображения | `encode_images(images, context)` | Тот же envelope, по вектору на изображение |
| Изображения | `encode_image_queries(items, context)` | Векторы запросов в том же пространстве |
| Reranker | `rerank(query, candidates, context)` | `[{candidate_id, score}]`, больше — релевантнее |
| OCR | `recognize(images, context)` | `[{id, text, regions?: [{text, bbox, confidence?}], confidence?}]` |
| ASR | `transcribe(audio, language, context)` | `{id, text, language, segments: [{start, end, text, confidence?}], confidence?}` |

Текстовые items имеют `{id, text}`, operation — `query` или `document`. Приложение
**уже добавило prefix ровно один раз**: не добавляйте инструкцию повторно.
Счётчик учитывает точный переданный текст, prefix и специальные токены. Чанки
по-прежнему ограничены 480 токенами и восемью содержательными сообщениями;
адаптер обязан принимать не менее 480 document tokens без молчаливого усечения.
Отдельный worker счётчика позволяет не грузить веса ради подсчёта: не загружайте
модель в `count_tokens`/`validate`. Data-only dry-run шума пока поддерживает
токенизаторы встроенных моделей.

Векторы должны сохранять порядок ID и размерность. Граница преобразует конечные
значения в float32 и проверяет L2-норму с допуском 0,001. Нулевые, переполненные,
NaN/Inf, потерянные, повторённые или переставленные строки не публикуются.

Изображение — `{id, width, height, mode: "RGB", pixels: bytes}`. OCR bbox — pixel
xyxy от верхнего левого угла в границах изображения; confidence необязателен и
лежит в `[0, 1]`. Кандидаты reranker — `{candidate_id, text}`; каждый ID возвращается
ровно раз. Равные оценки сохраняют исходный порядок кандидатов.

ASR получает `{id, sample_rate, samples, pcm: array('f')}`: конечный mono float32
PCM в `[-1, 1]` с sample rate из manifest. Язык запроса — `auto` либо объявленный.
Верните объявленный язык либо `und` для неизвестного/тишины. Сегменты упорядочены,
не пересекаются и ограничены длительностью входа; время в секундах, `0 ≤ start ≤ end`.
Пустой результат допустим. Декодирование файлов находится за пределами этого API.

## Ошибки, устройства и сборки

Ошибка импорта/устройства/контракта, таймаут или отмена останавливает затронутый
worker без частичной публикации векторов. Зависший native-вызов завершается,
а не просто теряет ответ браузеру. На Windows используется Job Object, на POSIX —
собственная process group и контроль родительского pipe. Песочницы прав это не создаёт.

Текст исключений и stdout/stderr могут содержать входные данные, поэтому они не
попадают в логи/ответы приложения. Возвращается фиксированная ошибка; для OOM
сохраняется безопасный признак автоматического уменьшения батча. Отлаживайте код
напрямую в его uv-окружении, если нужна подробная ошибка.

CPU/GPU текста используют одно пространство после проверки одинаковых входов.
Производительность пользовательского GPU не проверена; примеры работают только на
CPU. В готовых сборках окружение адаптера также остаётся отдельным.

## Пользовательское переранжирование в поиске

Зарегистрированные reranker появляются рядом с Giga и Jina. Необязательный этап
оценивает до 50 уже отфильтрованных текстовых/OCR-кандидатов каждой ветки перед
объединением модальностей. Для картинок и точных фраз действует прежний путь.
Батч — до четырёх кандидатов, дополнительно ограниченный `max_batch` manifest
и настройкой батча приложения.

Адаптер получает исходный запрос и тексты без embedding-префиксов. Поля
`input_contract.query_max_characters` и `document_max_characters` необязательны;
по умолчанию 8192 и 32768. Лимиты входят в identity обработки. Приложение обрезает
текст по этим лимитам и отмечает усечение; дальнейшее усечение токенизатором
выполняет адаптер. Он может вернуть булевы `truncated` и `query_truncated` для
каждой оценки. Оценки должны быть конечными и представимыми в float32; больше
означает релевантнее. Каждый исходный candidate ID возвращается ровно один раз.
При равных оценках сохраняется исходный порядок независимо от порядка ответа.

Используются устройство текстовых запросов и общая очередь вычислений. Для GPU
проверяется совпадение публичных CPU/GPU-оценок с абсолютной погрешностью 0.005;
при неудаче Авто переключается на CPU. Для эталона нужна поддержка CPU. Работа
на настоящем GPU ещё требует аппаратной проверки. Отмена завершает worker,
простой выгружает сессию. Ошибка модели сохраняет базовый порядок и безопасную
причину. Версии модели и окружения учитываются в кэше и истории. При исчезновении
пакета остаются доступны базовый поиск и выбор встроенной модели.
