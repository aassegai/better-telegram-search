### What's new

- OCR, image indexing and semantic OCR now have independent queues. Recognized text becomes searchable immediately, while its semantic index continues separately. Each OCR stage has its own pause, resume and error retry controls.
- E5 and CLIP prepare the next batch on CPU while the current batch runs. Background models share a device fairly, with interactive searches taking priority.
- Dialog settings now include OCR image and text-region batch sizes. Optional CPU OCR workers share one configured thread budget.
- Indexing diagnostics show individual queues, processing rates, stage timings and separate remaining-time estimates. Interrupted OCR work resumes from its checkpoint; deleting and reimporting a dialog cannot publish an outdated result.
- OCR workers retain their models longer, recover from memory pressure and save completed work when indexing pauses or the application closes.
- Existing model files, CPU/GPU embeddings, completed OCR caches and indexing progress remain compatible. Updating does not require reindexing.
