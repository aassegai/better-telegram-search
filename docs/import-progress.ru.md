# Прогресс импорта

[English version](import-progress.md)

**Импорт сообщений** принимает JSON одного диалога из Telegram Desktop.
Необязательная папка выгрузки — папка с `result.json` или родительская папка,
содержащая вложения. Проверка сразу создаёт сохраняемый отчёт, затем читает JSON.
Закрытие окна сохраняет задачу; вернуться к ней можно через **Открыть отчёт**
в боковом списке. **Открыть импорт** показывает последующую запись сообщений
и её отчёт.

Общий компонент показывает подготовку, проверку и запись:

- Чтение метаданных одновременно считает сообщения и хеширует JSON. Здесь
  показываются байты; отдельного прохода только ради общего числа нет.
- Проверка сообщений сравнивает редакции и проверяет вложения. Счётчик сообщений
  и прогресс текущего файла в байтах отображаются отдельно.
- **Проверка завершена** означает готовность отчёта к применению. Сообщения ещё
  не импортированы.
- Применение повторно проверяет JSON и редакции источника, затем ставит запись
  в существующую очередь импорта. **Импорт завершён** означает запись сообщений.
  Смысловые индексы, изображения и OCR имеют отдельный прогресс.

Счётчики соответствуют сохранённым контрольным точкам. Активное время сохраняется
при паузе и продолжении; время на паузе не прибавляется. Скорость и оценка времени
этапа появляются после трёх измеренных продвижений и одной секунды. При неизвестном
общем объёме процент не выдумывается. Текущая нативная проверка изображения может
закончиться перед обработкой паузы/отмены. Продолжение проверяет источник и
доходит до сохранённой позиции; изменённый JSON нужно проверить заново.

## HTTP-клиенты

Изменения требуют актуального `X-Session-Token` из `GET /api/session`;
проверки локального Host/Origin сохраняются. Браузер использует следующий путь:

1. `POST /api/import-previews`: `json_path` и необязательные `source_root`, `scope`,
   `target_chat_id`, `create_new`, `policy`. HTTP 202 сразу возвращает preview,
   включая незавершённую подготовку метаданных.
2. `GET /api/import-previews/{id}` показывает тот же preview на всех этапах
   подготовки и проверки. `POST .../{pause|resume|cancel}` управляет его задачей.
3. `POST /api/import-previews/{id}/apply?background=true`: HTTP 202 возвращает
   preview с `operation: "apply"`. Повторная проверка видна по прежнему ID.
4. После состояния `applied` поле `applied_import_id` ведёт на
   `GET /api/imports/{id}`. `POST /api/imports/{id}/{pause|resume|cancel}` управляет
   записью. Точные счётчики и конфликты остаются в отчёте.

Оба статуса содержат nullable `progress`: `phase`, `completed`, nullable `total`,
`unit`, `elapsed_seconds`, `phase_elapsed_seconds`, nullable `rate`,
`eta_seconds` и nullable `activity` текущего вложения. События содержат числа
и постоянные имена этапов; текстов сообщений и путей в них нет. Браузер опрашивает
статус каждые 500 мс без пересечения запросов. Прогресс сохраняется не чаще раза
в 250 мс с обязательной записью границ этапов; число записанных сообщений
уточняется по сохранённому checkpoint.

Совместимые `POST /api/imports` и apply без `background=true` сохраняют синхронную
начальную проверку. Для видимой подготовки нужен путь preview/background.
У старых задач после обновления со схемы 14 может быть `progress: null` до
продолжения; их завершённые состояния и позиции сохраняются. Миграция 015
добавляет колонки прогресса без перестройки сообщений или векторных индексов.

## CLI

```sh
uv run telegram-search --workspace /путь/к/workspace import /путь/к/result.json --preview
uv run telegram-search --workspace /путь/к/workspace import /путь/к/result.json
```

CLI получает те же события воркера и показывает `tqdm` в интерактивном stderr.
Stdout сохраняет агрегированный JSON-отчёт. При перенаправленном stderr полоса
выключена; явно отключить её можно через `--no-progress`. Прогресс не печатает
имена источников, пути или содержимое сообщений.
