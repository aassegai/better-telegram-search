# Сохранённые поиски

[English version](search-history.md)

**История поиска** сохраняет последние десять завершённых поисков и всё избранное
в текущем workspace. Избранный поиск отмечается заполненной жёлтой звездой.
Звезда относится к выполненному запросу, даже если в строке уже другой черновик.
Повтор с теми же условиями обновляет одну запись, сохраняя звезду. Ошибочные
и остановленные поиски не вытесняют завершённые.

**Открыть поиск** восстанавливает условия, доступную выдачу и загруженные страницы
в текущей вкладке без запуска моделей. **Открыть в новой вкладке** сохраняет текущую
вкладку. **Повторить поиск** явно запускает новый поиск. Неудачный
повтор сохраняет предыдущую выдачу и её связь с избранным. Пустые результаты
и просмотр сообщений с пустой строкой тоже сохраняются.

Снимок содержит фильтры, режим, модальности, выбор exact/ANN, параметры отображения,
время завершения, версии моделей и покрытие индекса. Поиск сохраняет до 100
результатов. Просмотр хранит последнее загруженное окно до 100 сообщений и курсор
продолжения. Обычный поиск восстанавливает уже показанное число результатов.
Один снимок ограничен 32 МиБ; изображения и аудиофайлы не копируются. Порядок
завершения хранится отдельно от времени часов: перевод часов назад не вытесняет
новейший поиск.

Снимки переживают перезапуск и истечение временных результатов задач. Продвижение
индексации не меняет старую выдачу незаметно — новые совпадения появятся по повтору.
Изменения/удаления в архиве, исключения авторов, смена embedding space, версии OCR
или условий ранжирования делают старую выдачу недоступной. Запрос и избранное
остаются. Лимиты CPU/GPU, батчи и новые значения отображения по умолчанию
не отменяют уже сохранённые результаты. Открытие и загрузка страницы проверяют
совместимость перед возвратом сохранённых сообщений.

В **Настройки → База → История и сохранённая выдача** есть отдельные действия:

- **Очистить сохранённую выдачу** удаляет постоянный и временный кэш результатов,
  сохраняя запросы и избранное.
- **Очистить историю** удаляет обычную историю и сохраняет избранное.
- **Очистить избранное** убирает звёзды; последние десять обычных поисков остаются.

Открытая вкладка удерживает свой ограниченный снимок отдельно от последних
десяти поисков. Удаление или вытеснение записи истории сохраняет её выдачу;
звезда может снова добавить этот поиск в избранное. Закрытие вкладки освобождает
её ссылку на снимок; снимки без владельцев удаляются. Очистка кэша результатов
делает недоступной и выдачу открытых вкладок.

Вкладки сохраняют независимые черновики, фильтры, результаты, прогресс,
пагинацию и прокрутку. Переключение не запускает модели. После перезапуска
восстанавливаются вкладки и активная вкладка; незавершённый поиск нужно запустить
явно. Доступно до восьми вкладок, вычисления используют общую ограниченную очередь.
Стрелки и Home/End переключают вкладки, Delete закрывает выбранную с клавиатуры.
Только несохранённые параметры временно дублируются в sessionStorage текущего окна
браузера для восстановления после перезагрузки во время сохранения. Сообщения,
выдача и вложения туда не копируются. Подробности — в [контракте вкладок](search-tabs-api.md).

## Локальный HTTP API

Изменения используют существующий session token и проверки локального Host/Origin.

- `GET /api/search-history?offset=0&limit=50`: страницы метаданных объединённой
  истории и избранного, без загрузки тел результатов в список.
- `GET /api/search-history/{id}`: метаданные и восстановленная выдача либо
  `result: null`, `cache_available: false` и причина недоступности.
- `GET /api/search-history/{id}?offset=20&limit=20&snapshot_id=...`: страницы
  результатов закреплённого снимка. Просмотр использует `cursor` вместо offset.
  Повтор такого же запроса не подмешивает новый снимок в прежнюю выдачу.
- `GET /api/search-history/{id}/status?snapshot_id=...`: только метаданные,
  включая звезду и доступность выдачи. Открытая вкладка проверяет собственный снимок
  раз в три секунды и перед повторным отображением после переключения.
- `POST /api/search-history/{id}/favorite`, тело `{"favorite": true|false}`:
  управление избранным выполненного поиска, HTTP 204 при успехе.
- `DELETE /api/search-history/collections/{history|favorites|cache}`: отдельная
  очистка выбранной коллекции, HTTP 204 при успехе.

Завершённая задача поиска возвращает `history_id`, `snapshot_id`, `completed_at`,
`favorite`, `applied_models` и `snapshot_coverage`. Старые job ID действуют только
в процессе; после перезапуска нужен ID истории. Совместимый синхронный
`GET /api/search` сохраняет временный кэш и не создаёт запись истории.

Миграция 016 добавляет таблицы SQLite для истории, снимков и владельцев без
перестройки сообщений или векторных индексов. Запросы и выдача — приватные данные
workspace, на них распространяется существующее исключение папки из Git.
