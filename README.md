# Better Telegram Search

Локальное приложение для поиска по JSON-экспорту Telegram Desktop: потоковый импорт,
SQLite FTS5/BM25, смысловой и гибридный поиск E5, поиск фотографий CLIP, русский/английский
OCR, фильтры и полный контекст. E5/CLIP работают через ONNX Runtime на CPU;
OCR — через CPU Tesseract. Q&A пока не реализован.

## Окружение

Python 3.11–3.13, uv и Node.js 22+ для сборки интерфейса. После сборки Node для запуска
не нужен. uv создаёт отдельное окружение `.venv` в репозитории.

```sh
uv sync --locked --extra semantic --extra ocr
cd frontend
npm ci
npm run build
cd ..
uv run --no-sync telegram-search setup
uv run --no-sync telegram-search run
```

Откройте приложение и нажмите «Импортировать экспорт». Введите путь к JSON, например
`test_chat_export/result.json` при запуске из корня репозитория. Папку можно указать
отдельно; по умолчанию используется родитель JSON. JSON должен лежать внутри этой
папки. Пути относятся к компьютеру с сервером, не к устройству с браузером.
Системный выбор папки пока не реализован; используется ручной ввод локального пути.
Нажмите «Проверить экспорт»: отчёт покажет новые, неизменённые, обновлённые сообщения
и конфликты до записи в архив. Затем нажмите «Применить изменения». Закрытый отчёт
можно снова открыть в боковой панели. Если диалог или JSON изменится после проверки,
создайте новый отчёт.

Также можно импортировать без браузера, **после остановки сервера**:

```sh
uv run --no-sync telegram-search import test_chat_export/result.json
uv run --no-sync telegram-search import test_chat_export/result.json --preview
uv run --no-sync telegram-search doctor
```

Готовые скрипты: `bash scripts/setup.sh`, `bash scripts/run.sh`; в PowerShell 7+
`pwsh -File scripts/setup.ps1`, `pwsh -File scripts/run.ps1`. Windows-скрипты добавлены,
но на этой машине не запускались. Установку uv см. в [официальной инструкции](https://docs.astral.sh/uv/getting-started/installation/).
Для Linux/WSL текущей машины uv установлен в `~/.local/bin`; добавьте этот каталог
в PATH, если новая оболочка ещё не видит `uv`.

Сервер запускается на `http://127.0.0.1:8765`; один процесс, без GPU и внешних API.
Для отдельного каталога данных: `uv run --no-sync telegram-search --workspace /path/to/workspace doctor`.
Для запуска: `uv run --no-sync telegram-search run --workspace /path/to/workspace --no-browser`.
Node после сборки интерфейса не требуется. Готовые файлы frontend/dist не хранятся в Git.

## Смысловой поиск

В настройках нажмите «Подготовить модель и индекс». Рекомендуется E5-small (~465 МиБ
файлов); E5-base (~1075 МиБ) требует больше памяти. Загрузка начинается только по
вашему действию. Содержимое переписки не отправляется наружу. Модель и tokenizer
закреплены revision и SHA-256; runtime не содержит PyTorch или sentence-transformers.

Без браузера, при остановленном сервере:

```sh
uv run --no-sync telegram-search prepare-model --profile small
uv run --no-sync telegram-search index
uv run --no-sync telegram-search prepare-model --offline
uv run --no-sync telegram-search prepare-model --profile base --reindex
uv run --no-sync telegram-search index --retry
```

`prepare-model` готовит модель; `index` обрабатывает сохранённую очередь. В UI очередь
выполняется автоматически, есть пауза, продолжение и повтор ошибок. При смене модели
или версии runtime требуется явная переиндексация. Пока она идёт, смысловой/гибридный
режим ищет только по готовым сегментам и показывает предупреждение; «По словам» и
«Точная фраза» доступны по всему архиву. Если готовых сегментов нет, выдача переключается
на поиск по словам с явным уведомлением.

После загрузки работа полностью offline. `--offline` использует только проверенный
локальный набор/кэш; `--local-bundle /path/to/bundle` импортирует набор с `manifest.json`
и теми же закреплёнными файлами. `--repair` позволяет заменить повреждённый набор.
Не запускайте обычный `uv run` после установки extra: uv может удалить optional пакеты.
Используйте `--no-sync` после `uv sync --locked --extra semantic --extra ocr`.
Минимальный профиль без моделей: `uv sync --locked`; поиск по словам работает отдельно.

## Фотографии, OCR и настройки

В настройках подготовьте OCR и поиск фотографий, затем выберите вкладку «Всё», «Текст»,
«Изображения» или «OCR» и нажмите «Найти». Русское описание фотографии использует
совместимую CLIP-пару; OCR ищется по словам, точной фразе и через E5. Результаты
показывают причины совпадения, распознанный текст, оригинальное фото и контекст.
Общая выдача объединяет независимые ранги через RRF. Числа покрытия показывают готовую
часть индекса; фотографии без распознанного текста не создают OCR embeddings.

CPU-профиль OCR проверен на Linux x86_64: wheel tesserocr включает native Tesseract,
словари rus/eng скачиваются автоматически по закреплённым SHA. Windows-профиль OCR
ещё требует подготовки; text/CLIP остаются доступны. macOS OCR здесь не проверялся.
Файлы CLIP (~853 МиБ) и словари OCR (~7.6 МиБ) находятся в workspace, вне приложения.
После подготовки поиск и OCR работают без сети. См. [детали CPU медиа](docs/media-cpu.md).

При остановленном сервере:

```sh
uv run --no-sync telegram-search prepare-media --kind ocr
uv run --no-sync telegram-search prepare-media --kind images
uv run --no-sync telegram-search index-media
uv run --no-sync telegram-search index-media --retry
```

`--offline` у `prepare-media` использует только проверенные локальные модели/словари.
Повторный импорт одинаковых фотографий переиспользует SHA-кэш. Пауза медиа и пауза
текста доступны отдельно; текущая фотография завершится перед остановкой.
В настройках меняются CPU-потоки, батчи, лимит времени/размер OCR, кэш запросов и
порог RAM для фоновой обработки медиа. Перед сохранением приостановите обе очереди.
Порог RAM является проверкой перед работой, а не жёстким лимитом памяти процесса.

Раздел источников проверяет SHA файлов и привязывает перемещённую папку. Изменённые
или ранее не проверенные файлы требуют повторного импорта. Незавершённый импорт
нужно отменить перед переносом. Настройки показывают размеры базы, векторов, моделей
и кэша; сведения обновляются кнопкой. Уплотнение удаляет старые версии медиа-кэша и
неопубликованные векторы. Удаление диалога сохраняет исходные экспорты и кэш фото,
используемых другими диалогами; окно подтверждения показывает логический объём данных.

[ONNX, offline и проверка моделей](docs/onnx-cpu.md),
[численные и поисковые CPU-замеры](docs/benchmarks/onnx-cpu.md).

## Данные

Экспорт исключён из Git, локальные планы находятся в игнорируемой `plans/`.
Рабочие данные находятся в игнорируемом `workspace/`.
Пути к папкам экспорта хранятся относительно workspace; исходные медиа не копируются.
Сохраняйте папки экспортов. SQLite и индекс содержат приватную переписку и не зашифрованы.
Тесты используют исключительно синтетические данные.
Workspace внутри любого Git-репозитория должен быть исключён **общим .gitignore**;
приложение проверяет это до создания базы. Для экспорта внутри checkout показывается
предупреждение, если папка не исключена. Локальные `.git/info/exclude` и global ignores
не заменяют общее правило. Приложение не выполняет git add/commit.

Повторный импорт идемпотентен. Разные аккаунты разделяются через `--scope`.
Новые редакции определяются по `edited_unixtime`. Неоднозначные изменения сохраняются
как конфликты; явно считать экспорт актуальным можно через `--prefer-imported`.
Отсутствие сообщения в частичной выгрузке не удаляет его из базы.
Задачи можно приостановить, возобновить или отменить. После рестарта прерванную задачу
можно продолжить из UI. Содержимое JSON не должно меняться до завершения задачи;
для изменённого файла создайте новый импорт. Кнопка «Разобрать конфликты» показывает
обе редакции и позволяет оставить текущую или явно принять импортированную.
Более старая редакция всегда становится конфликтом, даже при `--prefer-imported`;
применить её можно отдельным выбором в экране конфликтов. Выбор проверяет версию,
которую вы просмотрели, и не перезаписывает незаметно изменившееся сообщение.
CLI без `--preview` сразу запускает импорт; `--preview` оставляет локальный отчёт
для последующего просмотра и применения в UI.

Поиск по словам требует все слова;
«Точная фраза» требует непрерывный текст после нормализации регистра и ё/е. Даты
фильтров считаются в UTC; «по дату» включает весь выбранный день. Фильтры применяются
к одному совпавшему сообщению, соседние сообщения помечаются как контекст.
Авторы без from_id/actor_id сохраняются, но пока отсутствуют в выпадающем фильтре.
Режим «с фотографией» ищет текст/подписи сообщений, содержащих фото; содержимое фото
ещё не распознаётся. Оригиналы больше 32 МиБ и нерастровые вложения через API не выдаются.

```sh
uv run --no-sync pytest
uv run --no-sync ruff check .
uv run --no-sync telegram-search rebuild
uv run --no-sync telegram-search compact
```

Браузерные тесты (только synthetic fixtures, в отдельном временном workspace):

```sh
cd frontend
npx playwright install chromium
npm run build
npm test
```

Если в системе настроен HTTP proxy, включите localhost/127.0.0.1 в NO_PROXY.
Для frontend разработки: backend на 8765 и `npm run dev` из frontend; Vite proxy
сохраняет Host/Origin для локальных проверок безопасности.

[Архитектура и следующие этапы](docs/architecture.md), [CPU-замеры](docs/benchmarks/initial-cpu.md).
CI проверяет Python 3.11–3.13 на Linux/Windows/macOS и synthetic Chromium e2e на Linux.
Состояние удалённого CI после push нужно проверять отдельно.

Проверено на Linux/WSL x86_64. Windows и macOS требуют проверки на соответствующих
устройствах; отдельный semantic CI job добавлен для трёх ОС. Пользовательское окружение
не содержит PyTorch/CUDA. Сама установка окружения модели не скачивает.
